# Changelog — 2026-07

### 2026-07-01 — fix: bake the welded command plugins into the .rpm (arch parity)

The welded command plugins (`command:<word>` for doctor/clean/settings/candy/tmux/
preempt/feature/vm/secrets/udev) are out-of-process and resolve ONLY from
`bakedPluginDirs()` = `$CHARLY_PLUGIN_DIR` + `/usr/lib/charly/plugins`. The arch
PKGBUILD bakes them beside the binary; this `.spec` installed ONLY
`%{_bindir}/charly`, so on a fedora `dnf install ./opencharly-*.rpm`
`charly doctor`/`clean`/`vm`/… were unresolvable project-less ("unknown command").

- `%install` now installs the host-built welded plugins from the new `%{ovplugins}`
  define (the `/ovbin/plugins` bind mount the rpm `local_pkg.build_template` stages)
  into `/usr/lib/charly/plugins`, each binary 0755 + its `.providers` manifest 0644;
  `%files` owns `%dir /usr/lib/charly` + the recursive `plugins/` tree.
- The plugin SET is the shared single source `pkg/host-command-plugins.txt` in the
  superproject (R3) — the SAME list the arch PKGBUILD and the debian `.deb` build read;
  the spec just globs whatever was staged.

Proof (R8): built the rpm via the modified `build_template` (podman fedora:43 rpmbuild)
— `rpm -qlp` shows all 10 `plugin-*` + `.providers` under `/usr/lib/charly/plugins`
(0755 / 0644); `rpm -i --nodeps` + a project-less `charly doctor` dispatches the baked
`command:doctor` plugin (a binary-only install does NOT). Full welded-command
`charly check run` gate: `check-fedora-vm` (box/fedora) gained a
`welded-command-project-less` check step.
